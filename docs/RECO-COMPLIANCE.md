# RECO advertising compliance

Requirements for portal.corywong.ca, taken from the RECO advertising bulletins 5.1–5.6
(issued January 2024; copies in `docs/RECO Advertising Bulletins/`, current as of 2026-10-20).
Bulletins are guidance, not legal advice. The legislation is TRESA (Trust in Real Estate Services Act, 2002).
Check reco.on.ca for newer versions before relying on this.

The rules are shared with realestate.corywong.ca (`docs/RECO-COMPLIANCE.md` in that repo), which has the
fuller write-up. Keep the two in step. This file covers how the portal meets them and what's still open.

Under Bulletin 5.3 the portal's public pages (home, property search, listing pages, sign-in and
registration) are a **brokerage website**: Trustwell Realty Inc., Brokerage is responsible for them,
and Cory is too. Follow the brokerage's advertising policy where it is stricter than this doc.
Signed-in client pages and anything shared by link (tours, market snapshots, CMA exports) are held
to the same standard: they're the brokerage's communications to the public.

## Identity (5.1, 5.2, 5.3)

| Rule | How the portal meets it |
| --- | --- |
| Brokerage name on every page, clearly and prominently, exactly as registered, with "Brokerage" | `BrokerageBar` under the header and `ComplianceFooter` at the bottom, in the layouts for `/`, `/listings`, the auth pages and the client portal. Shared tour and snapshot pages and the CMA export name it directly. Checked by `npm run check:reco` |
| Agent's name exactly as registered with RECO; no nicknames, short forms or trade names | "Cory Wong, Broker". "Cory Wong Real Estate" is not a registered name and is now an error in the check. **Confirm the name matches the RECO registration exactly.** |
| Agent named with a permitted term | "Broker". Correct only while registered as a broker who is *not* the broker of record |
| "REALTOR®" only while a CREA member in good standing | Only inside CREA's trademark legend (footer, IDX disclaimer), which the check allows. See open item 3 |
| No advertising by or for a PREC; never imply RECO approved an ad (5.5) | Checked by `npm run check:reco` |

Names live in `src/lib/reco.ts`; `scripts/check-reco.mjs` has the same values and fails if they drift.

## Accuracy (5.1, 5.3)

Everything must be factual, verifiable and **current**. For the portal that mostly means describing
features as they actually work:

- Alerts are generated by a scheduled job (daily, at 12:00 UTC) and shown in the portal. No email is sent.
  The home page now says "alerts for new listings" instead of "instant alerts".
- Listing data comes from TRREB through the AMPRE IDX feed, with the attribution in `IdxDisclaimer`.
  Market snapshot numbers must name the source and period.
- Comparative claims, volume claims, awards and offers ("free", "guarantee"): see the realestate repo's doc.

## Listings, sold properties and consent (5.1, 5.3, 5.4)

- **Other brokerages' listings** (the IDX feed): credit the listing brokerage. Cards and detail pages show
  "Listed by {office}". Bulletin 5.3 also asks for the listing brokerage's contact details; see open item 4.
- **Sold properties**: the delta sync keeps listings after they sell or expire, but public listing pages
  and `/api/listings/[id]` now return only `ACTIVE` listings. Publishing "sold", or a sold price, needs
  written consent under 5.4, and the IDX licence doesn't cover sold data anyway.
- **CMA sold comps** are entered by hand. A CMA prepared for a client isn't public advertising, but
  the export and shared links can be forwarded. Don't put a sold price in anything shared without consent.
- Client names, photos and testimonials need written consent with an expiry date before they appear anywhere.

## Links and third parties (5.3)

Links off-site must not suggest you provide or endorse those services. Currently linked:
reco.on.ca, openstreetmap.org (map attribution). The check prints the list on every build.

**Open:**

1. **Alert frequency does nothing.** The saved-search form offers Instant / Daily / Weekly, but
   `generateAlerts` ignores the setting and runs once a day, and nothing sends email. Either build it or

2. **No privacy policy or terms.** Registration links to `/privacy` and `/terms`, which 404: the

   The portal collects names, emails and phone numbers, so PIPEDA needs a real, reachable privacy policy.
3. **REALTOR® / CREA membership.** The TRREB feed implies TRREB (and so CREA) membership. If Cory is a
   member in good standing, set `REALTOR_MEMBER = true` in the check; if not, the CREA legend should go too.
4. **Listing brokerage contact details.** Listing pages name the listing office but don't give its
   contact details, and say nothing when `listOfficeName` is empty. Check what the IDX rules require.
5. **Old documents.** Encrypted transaction documents stored on Vercel's `/tmp` were already lost; see README.

## Before publishing anything new

1. `npm run build` runs the RECO check first: fix errors and review warnings.
2. Any claim, number, award or comparison: is it true, sourced, dated and current?
3. Any person, property, price or someone else's photo: do you have written consent, with an expiry date, on file?
4. Unsure? Ask the broker of record. Only they can submit an ad to RECO for a courtesy review
   (Form 5.5.1; RECO does not review whole websites).

The check can't judge whether a claim is true or whether you have consent. That review is still yours.
